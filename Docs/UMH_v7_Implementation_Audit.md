# UMH v7 实现审计

## 结论

当前仓库已经形成可编译的 v7 固件骨架，设备描述、时空块、协议解析、帧环、播放计划、FPGA SPI、EEPROM、NOR Flash、OLED、按键和系统状态均已拆分为独立模块。它能够覆盖 v5 中的直接通道状态、空间点、状态查询、校准参数、启动、停止和清空等设备级能力。代码中没有引入具体应用名称或应用模式。

但当前实现还不能称为“完整实现了最初方案”。有三项原因来自项目当前已知边界，另外几项是实现与文档契约不一致。下面区分这两类问题，避免把硬件尚未确定的问题误当成软件已经完成。

## 本次修正

RGB 轨道使用 `SPARSE` 目标时，原实现会沿用未初始化的目标索引。现在稀疏目标统一采用显式长度和逐目标索引格式，常量颜色与亮度也遵循这一格式。

跨块播放时，原实现会把已经完成校准和亮度合成的 RGB 值再次当作原始颜色使用，导致校准重复生效。解析器现在保存未校准的逻辑颜色和亮度状态，并在每个输出帧重新合成。

`CHANNEL_STATE` 的 `component_mask` 现在真正控制相位、强度和使能字段的更新。空间轨道在几何能力未就绪时会在 `BLOCK_BEGIN` 阶段拒绝，而不是接收一部分数据后才失败。无载荷命令执行严格长度检查，未知协议标志会被拒绝。

播放计划现在以块头 `start_time` 作为源时间原点，首条记录相对块起点的时间差不会被错误地压缩为零。当前单一 FPGA 输出路由之外的 `route` 值会明确拒绝。FPGA SPI 链路增加静态互斥，协议任务发出停止命令时不会与播放任务的 DMA 事务重叠。SPI 启动失败、超时或 DMA 错误会进入输出故障状态并拉低 `TRIGGER`。OLED 初始化后的第一次刷新会覆盖控制器中可能残留的显示 RAM。

`ONCE` 的语义按设备需求保持为静态输出：计划调度结束后保留 FPGA 最后一帧，只有显式 `STOP` 或 `CLEAR_PLAN` 才关闭输出。

SSD1315 现在提供固定 5x7 ASCII 字体和文本绘制接口。新增的设备级 GUI 包含首页、播放、设备、校准、存储、诊断和控制页面，KEY0 至 KEY3 分别作为 Return、Confirm、Down、UP 使用。GUI 只调用播放计划和 FPGA 的既有动作接口，不包含任何应用专用语义，也不为播放数据增加本地生成路径。

## 尚未完整的部分

### 几何映射

`DeviceProfile` 现在直接使用 `Reference/UMH 7 Element Layout/umh7_element_map.h` 的 84 项理论六角晶格坐标，数组顺序为 `E01` 至 `E84`，并打开 `GEOMETRY_VALID`。坐标字段已改为 `int32_t`，可覆盖第五环的 ±45,000 µm。该表同时保留 `E## -> Tn -> FPGA ball` 关系，固件不会把 PCB 模块号当作阵元编号。几何能力因此可以用于空间点解算，但实际声学中心误差仍需设备加工后通过测量校准；生产资料中的 FPGA 料号和网表封装字符串不一致仍是硬件资料风险，不再阻塞固件引用参考表。

### FPGA 端

仓库只实现 STM32 侧 SPI 链路，没有 Lattice FPGA HDL、载波时钟域、FIFO、输出故障和 PDM 采样逻辑。因此 SPI 帧格式已经定义，但 84 路实时输出、RGB 时序、欠载安全动作和 CH347T 采样链路尚未经过端到端实现或联调。仅凭 STM32 编译成功不能证明硬件输出契约成立。

### 插值与规则采样

`interpolation` 和 `output_period` 字段已经进入协议，但当前块解析器只在记录时间戳发生变化时提交一个输出帧，不会根据 `LINEAR` 或 `STEP` 合成中间帧，`output_period` 也没有被消费。相位最短路径的数学约定目前只是协议约定，尚未在输出序列中执行。若上位机需要非均匀轨迹的设备端插值，必须先确定“按块时间还是按输出周期生成帧”的资源策略，再在编译器中加入可回压的帧生成流程；否则应在协议能力中暂时关闭 `LINEAR`，避免主机误以为设备会插值。

### 主机信用回报

块数据的 ACK 当前只带状态码、STM32 帧数量和剩余帧槽数量。FPGA FIFO 信用、FPGA 时间、当前块和解析错误原因需要通过 `FPGA_STATUS` 或 `GET_STATUS` 另行查询，没有完全实现方案中所描述的单次 ACK 全量信用回报。`LOOP_STREAM` 因而要求主机主动轮询状态并按帧环余量供数。

### 低优先级存储

NOR Flash 擦除和对象写入已经只在存储任务执行。EEPROM 提交仍由协议任务同步执行，一次完整副本写入会占用协议任务较长时间；如果在播放过程中提交校准，可能增加协议响应延迟。将 EEPROM 写入也纳入存储队列即可消除这一调度耦合，但需要同时定义待提交副本的队列所有权，不能只把现有指针直接异步化。

## 验证边界

本次只执行了 `make -j2` 交叉编译和链接容量检查。最终镜像使用约 73.5 KiB Flash，静态 RAM 约 105.3 KiB，低于当前链接脚本的 112 KiB RAM 区域。没有执行硬件、USB 行为、FPGA、OLED、EEPROM 擦写寿命或麦克风采样测试，这些项目在设备加工和 FPGA HDL 完成前无法由当前仓库证明。
